En una frase: Huellas en Casa ayuda a mostrar mascotas, recibir solicitudes de adopción y organizar el trabajo del refugio. Esta página es una explicación; no modifica ni reemplaza la aplicación.

01 · La idea general

Un lugar para encontrar un nuevo hogar

El sitio permite que las personas conozcan a las mascotas disponibles, lean sobre ellas y envíen una solicitud. El equipo del refugio puede revisar esas solicitudes y mantener actualizada la información.

La información no queda guardada solamente en la página que ves. El sitio la envía a un servidor, y el servidor la guarda en una base de datos para poder consultarla más adelante.

Una comparación: la página es el mostrador que usa el público; el servidor es el personal que recibe y revisa los pedidos; la base de datos es el archivador donde se guardan.

02 · Paso a paso

¿Qué hace una persona que quiere adoptar?

El recorrido típico desde que encuentra el sitio hasta que el refugio revisa su interés:

1. ExplorarVer las mascotas y buscar por nombre o especie.
2. ConocerAbrir el detalle para leer la información de una mascota.
3. RegistrarseCrear una cuenta e iniciar sesión como adoptante.
4. SolicitarConfirmar el interés y explicar por qué quiere adoptar.
5. RevisarEl refugio evalúa la solicitud y actualiza su estado.

Buscar mascotas

En el catálogo se puede filtrar por perro o gato, buscar por texto y ver cuáles están disponibles o marcadas como urgentes.

Guardar favoritas

Una persona con cuenta puede guardar mascotas para encontrarlas fácilmente después. Puede quitar una de sus favoritas cuando quiera.

Seguir una solicitud

La persona puede consultar sus solicitudes y ver si siguen pendientes, fueron aprobadas o fueron rechazadas.

Completar el perfil

El perfil reúne datos útiles para el proceso, como teléfono, tipo de vivienda, actividad y si hay niños en casa.

03 · Las personas y sus permisos

Hay dos tipos principales de cuenta

Adoptante

Puede consultar el catálogo, guardar favoritas, enviar solicitudes y revisar o editar su perfil.

Administrador del refugio

Puede agregar o actualizar mascotas, gestionar solicitudes, consultar adoptantes y ver estadísticas generales.

Una persona que todavía no inició sesión puede ver la información pública y registrarse o ingresar. Las acciones personales requieren una cuenta.

04 · Qué hay detrás de la pantalla

Las piezas del sitio, explicadas fácil

HTMLSon las páginas y los formularios que se ven en el navegador.
css/styles.cssDefine los colores, tamaños, tarjetas, menú y cómo se acomodan las páginas en celulares.
js/Son instrucciones para que el navegador responda a búsquedas, botones y formularios.
api/Recibe pedidos del sitio, por ejemplo “mostrar mascotas” o “guardar esta solicitud”.
modelos/Contiene las operaciones que consultan o actualizan la información guardada.
config/Reúne ajustes de conexión y herramientas para responder y comprobar permisos.
base_de_datos/huellas.sqlDescribe cómo se organiza la base de datos y contiene algunos datos iniciales.
img-mascotas/Guarda las imágenes que se muestran en las fichas y las fotos que sube el administrador.
admin/ y usuario/Contienen las páginas para el trabajo del administrador y las funciones de cada adoptante.
Cómo viaja un pedido: el navegador envía una petición a la API; la API revisa quién la hizo y qué necesita; después consulta o actualiza la base de datos y devuelve una respuesta.

05 · La información

¿Qué cosas guarda el sistema?

GrupoQué representa
PersonasLa cuenta, datos de contacto y perfil. Las contraseñas se guardan protegidas, no como texto común.
MascotasNombre, especie, edad, descripción, foto y estado de adopción.
FavoritasLa relación entre una persona y las mascotas que guardó.
SolicitudesQuién se interesó por qué mascota, cuándo y cuál es el estado de la solicitud.

Así se conectan esos datos: una persona puede enviar varias solicitudes; cada solicitud corresponde a una mascota. También puede guardar varias mascotas favoritas.

Los estados de las mascotas son Disponible, En proceso y Adoptada. Las solicitudes pueden quedar Pendientes, Aprobadas o Rechazadas.

06 · Cuidado de las cuentas

¿Cómo se controlan los permisos?

El sistema usa una sesión para recordar que una persona inició sesión. Las páginas pueden mostrar opciones según el tipo de cuenta, pero la comprobación importante también se hace en el servidor antes de realizar acciones privadas.

  • Solo una cuenta autorizada puede ver sus datos privados o sus solicitudes.
  • Las acciones de administración requieren una cuenta administradora.
  • Las contraseñas se guardan mediante una transformación de seguridad, en vez de guardarse directamente como fueron escritas.
  • El servidor valida los datos recibidos y puede rechazar pedidos incorrectos o sin permiso.

Por ejemplo, “no has iniciado sesión” y “no tienes permiso para administrar” son situaciones distintas; el servidor las reconoce y responde de manera diferente.

07 · Preparar el proyecto original

¿Qué se necesita para que funcione completo?

El proyecto principal no es solamente un conjunto de páginas. Para que funcionen el registro, el inicio de sesión, las solicitudes y la administración, también hace falta un servidor que pueda ejecutar PHP y una base de datos MySQL o MariaDB.

  1. Colocar el proyecto en una carpeta servida por Apache.
  2. Encender Apache y MySQL/MariaDB, por ejemplo desde XAMPP.
  3. Importar el archivo base_de_datos/huellas.sql en la base de datos.
  4. Revisar config/conexion.php para que coincidan los datos de conexión del entorno.
  5. Abrir el sitio desde una dirección web del servidor, no desde un archivo local con file://.
Importante: las credenciales incluidas en la configuración son para desarrollo local. Antes de publicar el sistema completo, la persona responsable del hosting debe configurar credenciales propias y seguras.

08 · Una diferencia importante

¿Qué significa “página estática”?

Una página estática es un archivo que el navegador puede mostrar sin que un servidor ejecute código de backend. Esta guía está hecha de esa manera: es un HTML con sus estilos incluidos y no necesita conectarse a la base de datos.

El proyecto completo sí necesita PHP y MySQL/MariaDB para iniciar sesión, guardar favoritas, crear solicitudes y administrar información. Si se suben únicamente sus archivos HTML, CSS y JavaScript a un hosting que solo ofrece páginas estáticas, esas funciones no tendrán el backend que necesitan.

En resumen: esta guía se puede mostrar como página estática; para que toda la aplicación de adopciones funcione, hay que contratar o configurar un hosting compatible con PHP y una base de datos.

09 · Cómo se ve

Se adapta a celulares y permite cambiar el tema

Las páginas del proyecto comparten estilos para que los menús, tarjetas, formularios y tablas tengan una apariencia coherente. El diseño se reorganiza en pantallas pequeñas para que se pueda usar desde un teléfono.

La aplicación también incluye un selector de apariencia con modo claro u oscuro y varias paletas de color. La preferencia elegida se guarda en el navegador para conservarla en la próxima visita desde ese mismo dispositivo.

10 · Cómo leer los archivos

Algunas aclaraciones sobre la carpeta

  • estructura.md es el documento que explica la organización técnica del proyecto.
  • No hay un archivo llamado carpetas.txt. La lista de carpetas está escrita en el documento Markdown.
  • Los archivos con extensión .txt que aparecen en la carpeta son auxiliares o copias de texto; las páginas cargan los archivos .css y .js.
  • Algunas páginas de usuario están en la raíz y otras, más completas, están dentro de usuario/. Para los flujos conectados a la cuenta, se usan las páginas de esa carpeta.

La aplicación principal sirve para gestionar el proceso de adopción. Esta página, en cambio, solo lo explica de forma informativa.

11 · Palabras técnicas, sin vueltas

Diccionario rápido

Frontend
La parte del sitio que la persona ve y usa en su navegador.
Backend
La parte que trabaja en el servidor: revisa pedidos y aplica reglas.
API
El canal por el que la página y el servidor se envían pedidos y respuestas.
Base de datos
Un conjunto organizado de información que el sistema puede guardar y consultar.
Sesión
El recuerdo temporal de que una persona ya inició sesión.
Hosting
Un servicio que mantiene los archivos del sitio disponibles en Internet.
Responsive
Un diseño que se acomoda a distintos tamaños de pantalla.
Endpoint
Una dirección concreta de la API que realiza una tarea, como listar mascotas.
